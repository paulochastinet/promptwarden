# Contributing to promptwarden

Thanks for helping make AI agent tooling safer! Bug reports, false-positive reports, new
detection ideas and pull requests are all welcome.

## Development setup

```bash
git clone https://github.com/paulochastinet/promptwarden.git
cd promptwarden
npm install          # also builds dist/ via the prepare script
npm test             # vitest
npm run typecheck    # tsc --noEmit
npm run build        # tsup -> dist/
node dist/cli.js examples   # see the demo output
```

Requirements: Node.js >= 18.18.

## Project layout

```
src/
  cli.ts              argument parsing, output, exit codes
  scanner.ts          scan(): discovery -> per-file detectors -> suppression -> findings
  discover.ts         which files are agent files (patterns + classify())
  context.ts          per-file context (line index, markdown code blocks, frontmatter, JSON/TOML trees)
  text.ts             invisible-character rendering, secret patterns and masking
  rules/meta.ts       rule metadata (id, severity, description, remediation...) <- single source of truth
  rules/*.ts          detectors grouped by theme (hidden, injection, commands, secrets, mcp, settings, skills)
  formatters/         text, json, sarif, markdown
test/
  fixtures/rules/PWxxx/{bad,good}/   one malicious + one clean fixture per rule
docs/rules.md         generated by `npm run docs`
```

## How to add a rule

1. **Pick the next id** (`PW031`, ...) and add a `RuleMeta` entry in `src/rules/meta.ts`:
   `id`, kebab-case `name`, `title`, default `severity`, `category`, `description`, `remediation`,
   `appliesTo` (file kinds) and a couple of `examples`.
2. **Implement detection** in the most fitting `src/rules/*.ts` file. Text rules can usually be a new
   entry in the `PATTERNS` array in `src/rules/commands.ts`; structural rules (JSON/TOML/frontmatter)
   belong in `mcp.ts`, `settings.ts` or `skills.ts`. A detector returns `RawFinding`s with character
   offsets — the engine computes line/column, snippets, masking, suppression and fingerprints.
3. **Add fixtures**: `test/fixtures/rules/PW031/bad/...` must trigger the rule and
   `test/fixtures/rules/PW031/good/...` must not. Use file names that discovery recognises
   (`SKILL.md`, `CLAUDE.md`, `.mcp.json`, `.claude/settings.json`, `skill/scripts/x.sh`, ...).
   The test suite iterates every rule automatically and fails if fixtures are missing.
4. **Regenerate docs**: `npm run docs` and commit `docs/rules.md`.
5. **Check false positives**: run the scanner against real projects and your own `--home`
   (`node dist/cli.js --home ~/code`). Good rules are *boring* on legitimate repos.
6. Add a line to `CHANGELOG.md` under *Unreleased*.

### Rule design guidelines

- **Low false positives beat coverage.** A noisy rule gets disabled and protects nobody.
  Prefer concrete patterns (`curl ... | sh`) over vague ones (`curl`).
- Respect context: use `negatedInProse()` for markdown prose ("never run `rm -rf ~`"), skip comments
  in scripts, downgrade quoted examples, and use per-finding `severity` overrides when the risk differs.
- Be fast and safe: avoid catastrophic backtracking (no nested unbounded quantifiers), keep matches on
  a single line (`[^\n]*`), and never execute or `eval` scanned content.
- Never print secrets: return the raw value in `mask` so every formatter redacts it.
- Fixtures must be harmless: use `example.invalid`, documentation IPs (`192.0.2.0/24`) and fake tokens.

## Reporting false positives

Open a [false positive issue](https://github.com/paulochastinet/promptwarden/issues/new?template=false_positive.yml)
with the smallest snippet that reproduces it (redact anything private). Until it's fixed you can suppress it
with `<!-- promptwarden-ignore PW0xx -->` or `.promptwardenignore`.

## Commit style

[Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).

## Code of conduct

Be kind and assume good intent. Harassment of any kind is not tolerated.
